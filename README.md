# 【ポートフォリオ用】AI駆動型・自動ナレッジ構造化データベースシステム

## 1. システム概要
本システムは、日々生まれる未整理の断片情報（インボックスデータ）をAIに解析させ、定義されたフォルダ・ファイル構造を持つナレッジベース（Googleドキュメント群）へ完全自動で分類・統合・更新する**「自律型ナレッジ・インテグレーション・システム」**です。

格闘ゲーム（Street Fighter 6）の高度な戦術データ管理をモデルケースとし、人間の手によるコピペや分類の手間をゼロにしながら、ナレッジの陳腐化を防ぎ、常に最新かつ構造化されたデータベースを維持します。

## 2. 解決した課題
- **ナレッジ管理の形骸化防止**: メモを取っても整理が追いつかず、死蔵データ化してしまう課題をAIの自動分類で解決。
- **データ更新時の構造破壊防止**: 既存ドキュメントの文脈を壊さず、新旧データをインテリジェントに融合。
- **APIコストと手間の最適化**: NotebookLMによるドキュメント全体のセマンティック検索（意味的理解）と、GASによるピンポイントなドキュメント操作を組み合わせることで効率化を達成。

---

## 3. システムアーキテクチャと動作フロー

1. **Input (00_インボックス)**: ユーザーが音声入力やメモ書きした未整理のテキストを投入。
2. **AI Analysis & Transformation**: 
   - 独自のプロンプト（Ver. 6.3）を用いて、AIがインボックス内のデータを「どのファイルのどのセクションに、どう更新すべきか」を解析。
   - 更新アクション（`REPLACE`/`APPEND`/`INTEGRATE`）を判定し、構造化されたMarkdownとして出力。
3. **Automated Execution (GAS)**: 
   - Google Apps ScriptがAIの出力をパース。
   - 対象ドキュメント内のセクション（IDを兼ねた番号付き見出し）を検索し、コンテンツを動的に差し替え・追記。
4. **Knowledge Source (NotebookLM)**: 更新されたGoogleドキュメント群をNotebookLMが常時同期。ユーザーはいつでも「最新のデータベース」を元にした高精度なAI壁打ちが可能。

## 4. 使用技術（Tech Stack）
- **Core Engine / Prompt Engineering**: 
  - NotebookLM (LLMを活用したドメイン知識のセマンティック検索・要約)
  - 高精度プロンプト（構造定義、エラーハンドリング制約、フォーマット厳守）
- **Automation / Backend**: 
  - Google Apps Script (GAS) 
  - Google Docs API (DocumentApp)
- **Data Structure**: 
  - Markdown, HTML-like tags (Mermaid.js、テーブル記法への将来的な拡張性を内包)

## 5. 技術的アプローチと工夫した点（アピールポイント）

### ① プロンプトによるシステムエラー（GASバグ）の徹底制御
プログラム（GAS）がテキストを正確にパースできるよう、AIの出力フォーマットを厳密に制御するプロンプトを設計。`[Target File]` や `[Target Section]` といったメタデータを付与させ、正規表現や構文解析のエラーを最小限に抑えました。

### ② セクション番号をIDとした「インデックス同期アルゴリズム」
Googleドキュメント内の見出し（例: `6. 起き攻めシミーにおける...`）に含まれる「セクション番号」をユニークIDとして扱わせるルールをプロンプトに実装。AIが見出しの文言を勝手に要約・変更してしまい、GASが更新対象を見失う（404エラーやセクションの重複作成）という致命的なバグを克服しました。

### ③ 状況に応じた3つのデータ更新モード（Action）の設計
一様一律の追記ではなく、データの性質に応じて自動で処理を分岐させるロジックを確立。
- `REPLACE`: 古い・間違ったデータの完全上書き。
- `APPEND`: 既存セクションの末尾への純粋な追記（ドキュメント末尾削除エラーの回避策を内包）。
- `INTEGRATE`: 既存データと新規データをAIが脳内でマージし、1つの綺麗なセクションへ再構成。

## 6. 今後の展望・拡張性
- **幾何学データ（図解）の自動生成連携**: 
  NotionやVS Code（Draw.io）との連携を想定し、AIにMermaid.jsコード（`curve: linear` などの直線化制御コードを含む）を生成させることで、文字だけでなく「判断の分岐図（ロジックツリー）」までを自動構造化するフローへの拡張が可能です。
